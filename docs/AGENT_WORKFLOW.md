# Multi-agent workflow (Herdr + Claude Code)

How we run a lead Claude session that spawns and coordinates subagents in one terminal, based on
https://blog.keerthivibisan.com/agentic-ai/herdr-multi-agent/ and adapted for native Windows.

A **lead** agent plans and splits the work. **Subagents** (more Claude sessions) each own a piece in their own
pane. [Herdr](https://herdr.dev) tracks which agent is idle, working or blocked, and lets the lead drive the others.

## One-time setup (per machine)

The skills and hook live in the developer's own `~/.claude` folder, not in this repo.

1. **Install Herdr** (PowerShell). Read the script first if you prefer:
   `powershell -ExecutionPolicy Bypass -c "irm https://herdr.dev/install.ps1 | iex"`
   Then open a new PowerShell window and check `herdr --version`. macOS/Linux: `curl -fsSL https://herdr.dev/install.sh | sh`.
2. **Connect Claude Code:** `herdr integration install claude` (adds a harmless `SessionStart` hook).
3. **Herdr skill:** `herdr --skill` and save the output as `~/.claude/skills/herdr/SKILL.md`
   (write it as plain UTF-8; it is regenerated by Herdr updates).
4. **Lead protocol skill** `~/.claude/skills/herdr-lead-windows/SKILL.md`: the rules the lead follows (naming,
   registry, background waits, ask-before-approving). It only activates when you ask for Herdr subagents.
5. **Stop hook** `~/.claude/hooks/herdr-subagent-report.ps1`, registered under `hooks.Stop` in
   `~/.claude/settings.json`. When a registered subagent finishes a turn it sends a one-paragraph report to its lead.
   It does nothing in a normal session (needs `HERDR_ENV=1` and a registry file for the pane).

Requires Windows 10/11 x86_64 (Herdr's Windows support is beta) and a working Claude Code login.

## Running it

```powershell
herdr                                   # open Herdr in a new PowerShell window
cd <repo>; claude                       # in a Herdr pane: this session is the lead
```

Then ask for it by name, for example:

```
use herdr, spin up 3 claude subagents ... (see the examples below)
```

The lead splits panes, registers each subagent, sends tasks, and tells you what each one did. Start with **two or
three** subagents: each is a full session and costs tokens and memory (our API test suite is heavy).

## Rules for this repo

1. **One owner per file.** Subagents share one checkout. The lead gives every subagent a disjoint set of files and
   says so in the task.
2. **Shared files belong to the lead:** `apps/mobile/src/i18n/index.ts`, `apps/mobile/src/theme/index.ts`,
   `apps/mobile/src/components/ui/**`, `apps/mobile/src/services/api.ts`, `apps/mobile/src/store/**`,
   `apps/mobile/app/(app)/_layout.tsx`, `packages/shared/**`, lockfiles. Subagents that need a change there (for
   example new English and Tamil strings) put it in their final message and the lead applies it.
3. **Lead verifies before reporting.** Run `npx -y pnpm@9.0.0 --filter @ti/mobile type-check` (and the relevant API
   tests) on the combined result.
4. **Blocked agents ask the human.** The lead never approves a subagent's permission prompt on the user's behalf.
5. **Business rules still apply** (see `CLAUDE.md`): client isolation, approval gate, handover proof, manual SLA.
   Never commit `.env` files or secrets, and no co-author lines in commits.
6. **Clean up.** The lead closes only the panes it created and deletes their registry files.

## Starter prompts

**Remaining mobile screens** (disjoint files):

```
use herdr, spin up 3 claude subagents on branch feature/mobile-ui:
1. Tasks screen: rebuild apps/mobile/app/(app)/tasks/index.tsx with the UI kit in src/components/ui
   (own: that file only). Show only the signed-in user's tasks, grouped by status.
2. Handover inbox and Blockers: build apps/mobile/app/(app)/handovers/index.tsx and
   rebuild apps/mobile/app/(app)/blockers/index.tsx (own: those two files only).
3. Chat: restyle apps/mobile/app/(app)/chat/** and projects/[id]/chat.tsx (own: those files only).
Do not edit i18n, theme, ui kit or the tab layout: send me the new EN/TA strings you need.
Check the combined result with the mobile type-check before reporting.
```

**Production-readiness chores:**

```
use herdr, spin up 3 claude subagents:
1. add an ESLint config and a lint step to .github/workflows/ci.yml (own: eslint configs, ci.yml)
2. write docs/BACKUP_RESTORE.md for MongoDB Atlas (own: docs/BACKUP_RESTORE.md)
3. write failing tests for the open PR #6 review fixes (own: apps/api/test only)
```

## Troubleshooting

- *"Not running inside a Herdr pane"*: start `claude` from a pane inside the `herdr` UI, not a normal terminal.
- *No "turn finished" report*: check the pane has a registry file in `%USERPROFILE%\.cache\herdr-leads`, and that
  `herdr integration status` shows `claude: current`.
- *Too many agents / machine slow*: keep to two or three, or close panes you no longer need.
